# glossary 設計

## 要解決的問題

agent 在對話裡常常提到工單編號、檔案路徑、專案內部的說法。讀者每看到一個，就得離開對話去查它是什麼。這個 mod 讓這些參照在 Claude Code 的畫面上直接變成連結，滑鼠移到段落上還會跳出一張卡片，說明這段提到的東西是什麼。

分工的原則是：agent 只管寫字，連結和卡片內容一律由 mod 產生。連結網址不經過模型，所以模型不會寫錯網址。卡片上的工單標題直接從 Plane 抓，也不經過模型。

## 三種參照

| 種類 | 怎麼認出來 | 連結指向 | 卡片內容 |
|---|---|---|---|
| 工單 | 設定檔裡的前綴規則，例如 `CK-12` | Plane 上那張工單的網頁 | 標題和狀態，從 Plane API 抓 |
| 檔案路徑 | 渲染時檢查磁碟上存在 | 用 VS Code 打開並跳到那一行 | 被引用的那一行程式碼 |
| 專案名詞 | 名詞庫裡登記過的詞 | 條目的 `target` | 條目的 `summary` |

工單和檔案都不需要登記，只有專案名詞需要。

相對路徑先在 session 的根目錄底下找。找不到時，再到這個 session 讀過或改過的檔案所屬的 repo 裡找，最近碰過的優先。原因是 session 常常從上層資料夾開，agent 寫的卻是某個 repo 裡的相對路徑。一個檔案屬於哪個 repo，判斷方式是往上層找第一個有 `.git` 的資料夾。resume 的 session 會從逐字稿把這份清單重建回來。

## 設定檔

分兩層，repo 那層優先：

- `~/.claude/glossary.json`：工單規則、跨 repo 通用的名詞。
- `<repo>/.claude/glossary.json`：這個 repo 專屬的名詞，進版控。agent 新增的條目會出現在 git diff 裡，這是擋住錯誤條目的主要關卡。

格式用 JSON，不用原本討論時舉例的 TOML。原因是 mod 的執行環境不能裝套件，JSON 不用另外寫解析器。範例在 `examples/glossary.example.json`。

Plane 的 API 金鑰不放在設定檔裡，設定檔只寫金鑰檔的路徑（`tokenFile`）。

## 名詞條目

```json
{
  "name": "車籍表",
  "aliases": ["車籍", "vehicle registry"],
  "target": "docs/vehicle-registry.md",
  "summary": "每台車的參數收成一張表，取代散落各處的常數"
}
```

`name`、`target`、`summary` 必填，`aliases` 選填。分類、建立時間、建立者不放，git 都記得。

## 登記工具

- 驗證 `target` 存在就直接寫入，不跳確認框。
- 同名而且 `target` 不同時拒絕寫入，把現有條目回給 agent。改既有條目只能由人來改，或人明確要求 agent 改。
- 每輪結束時，由 mod 自己在逐字稿加一行暗色通知，列出這輪新登記的詞。原本討論的是讓 agent 在回覆結尾列出，改成 mod 做的原因是 mod 親眼看到每一次寫入，不用靠 agent 記得回報。這行通知不會送給模型。
- 工具的用法透過系統提示詞告訴 agent，不把整份名詞清單塞進提示詞。

## 標記規則

- 每則回覆只標第一次出現的地方。實作上以 Claude Code 的一個回覆區塊為單位，也就是兩次工具呼叫之間的那段文字。
- 程式碼區塊、行內程式碼、已經是連結的地方、網址裡面，一律不標。
- 長的詞優先比對，「車籍表」不會被「車籍」切開。

## 懸停卡片

- 以段落為單位：滑到某一段，就跳出這段提到的所有參照。原因是 Claude Code 的 `Markdown` 元件不能在內部放可懸停的盒子，要精確到單一個詞就得放棄內建的 markdown 排版。
- 沒有延遲，游標一移上去就出現。
- 工單資料在這個 session 裡快取，同一張只抓一次，代價是 session 中途改了狀態會顯示舊的。連不到 Plane 時卡片只顯示編號。

Herdr 裡懸停可以用（使用者手動測過）。原本預留的 `/refs` 側邊面板因此不做。

## 點擊

- 工單是 `http(s)` 連結。在 Herdr 裡 ctrl+點擊由 Herdr 自己開瀏覽器。
- 檔案是 `file:` 連結，行號放在網址的 `#L42` 片段裡。**用一般左鍵單擊**，由 mod 攔下來執行 `code -g 路徑:行號`，VS Code 會在最後使用的視窗打開並跳到那一行。只有全螢幕模式會回報一般點擊，Herdr 會把一般點擊傳進來（使用者實測過）。
- 點擊被 mod 收到時會先跳出「用 VS Code 打開 …」的提示。原因是 Claude Code 要等雙擊的判斷時間過了才把點擊交出來，畫面沒反應的話人會再點一次，兩下太近就變成雙擊，點擊被取消。
- ctrl+點擊不會交給 mod，Claude Code 照舊交給終端機。在 Herdr 裡，ctrl+點擊 `file:` 連結會被 Herdr 攔走，又不交給系統開啟，所以什麼都不會發生。要支援就得另外寫一個 Herdr 外掛來接，目前沒做。
- 反引號裡如果整段就是一個路徑，連結會包住整段，保留程式碼的樣式。

## 階段

1. 工單：連結和卡片。同時驗證 Herdr 的滑鼠行為和 Plane 連線。
2. 檔案路徑：連結、點擊開 VS Code、卡片顯示那一行。
3. 專案名詞庫：兩層設定檔、登記工具、系統提示詞說明。
